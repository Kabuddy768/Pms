# Open Decisions & Approved MVP Policies

**Status:** Approved for MVP implementation. Changes to approved financial, tenancy, or compliance rules require an ADR or explicit stakeholder sign-off.

| ID | Decision | Approved MVP Policy | Status |
| :--- | :--- | :--- | :--- |
| **D-001** | **Initial customer** | Support both **individual landlords** and **property management agencies**. Both are modeled as an `Organization` with one or more `OrganizationMembership` records. | Approved |
| **D-002** | **Property types** | **Residential first for MVP** (simpler lease and tax rules). `property_type` supports `RESIDENTIAL`, `COMMERCIAL`, and `MIXED` on the model so commercial extensions remain non-breaking. | Approved |
| **D-003** | **Tenancy strategy** | **Shared PostgreSQL schema with `organization_id` FK** on every organization-owned table. Cross-tenant isolation is enforced in service/queryset layers and verified with negative tests. | Approved |
| **D-004** | **Lease rules** | Monthly billing cycle by default with configurable due day (e.g., 5th of the month). Full month rent by default, with optional manual proration on move-in. **Strict no-overlap rule:** a unit may have at most **1 `ACTIVE` lease** at a time. | Approved |
| **D-005** | **Late fees** | Optional per property/lease (default: **Off**). When enabled later, supports configurable grace period and fixed or percentage fee. Deferred to fast-follow after core billing. | Approved |
| **D-006** | **Deposits** | Tracked in a dedicated `DEPOSIT_ACCOUNT` and immutable `DEPOSIT_TRANSACTION` ledger per lease (`RECEIVED`, `DEDUCTED`, `REFUNDED`). Never mixed with monthly rent revenue until explicitly applied at move-out. | Approved |
| **D-007** | **Payments** | Support **M-Pesa Paybill/Till (C2B)**, **Bank Transfer/Deposit (PesaLink/EFT)**, **Cash**, and **Cheque**. **M-Pesa STK Push is explicitly excluded** because tenants pay directly to Paybill or bank accounts on their own schedule. Include manual/assisted entry, **Bank/Paybill CSV Statement bulk reconciliation**, strict duplicate reference protection, and an unmatched/suspense queue for C2B typos. | Approved |
| **D-008** | **Allocation** | **Automatic FIFO (oldest unpaid invoice first)** by default, with an option for authorized managers/accountants to manually allocate to specific invoices. | Approved |
| **D-009** | **Overpayments** | Remain as **Unallocated Credit Balance** on the payment/lease and automatically apply to future invoices. Refunds require an explicit authorized reversal/refund record. | Approved |
| **D-010** | **Approvals & Roles** | Four organization roles: `OWNER` (full admin), `MANAGER` (operations, reversals, adjustments, lease amendments), `ACCOUNTANT` (billing, payments, expenses), `CARETAKER` (read portfolio, log maintenance, submit meter readings & pending payment refs). Reversals and adjustments require `OWNER` or `MANAGER`. | Approved |
| **D-011** | **Ownership** | A property may have one or more `OWNER` records via `PROPERTY_OWNER`. When owners are attached for an active period, `ownership_share` percentages must sum to `100.00%`. | Approved |
| **D-012** | **Tenant access** | **Deferred post-MVP.** Tenants receive invoices, receipts, and statements via PDF/WhatsApp/SMS/Email rather than logging into a self-service portal in V1. | Approved |
| **D-013** | **Communications** | **Email + SMS + WhatsApp share link boundary** for invoice notifications and payment receipts, with consent/opt-out flags on tenant profiles. | Approved |
| **D-014** | **SaaS commercial model** | **Admin-provisioned organizations for MVP.** Store `plan_tier` and `unit_limit` on `ORGANIZATION`; defer self-serve subscription checkout until post-MVP. | Approved |
| **D-015** | **Privacy / Kenya ODPC** | Minimize PII (Name, Phone, Email, optional National ID / KRA PIN masked/protected). Strict tenant isolation, audit logging on sensitive mutations, and data retention controls. | Approved |
| **D-016** | **DataTables & Drawers** | All back-office list views must use a reusable server-driven `DataTable` component (search, filter pills, sortable columns, server-side pagination beyond 25 items, and CSV export) paired with **slide-over detail drawers** instead of cramped inline table forms. | Approved |
| **D-017** | **DB Indexing & Concurrency** | Enforce composite `(organization, ...)` indexes on high-volume tables (`INVOICE`, `PAYMENT`, `EXPENSE`, `MAINTENANCE_REQUEST`) and row-level locking (`SELECT ... FOR UPDATE`) + `IntegrityError` idempotency guards on unit caps, monthly billing batch runs, and webhook callbacks. | Approved |
| **D-018** | **Landing Page & Auth** | Serve a public architectural landing page at `/` (with background API readiness warm-up and 1-click Demo Workspace sign-in). Keep email/password JWT primary; provide a clean integration slot for **Google Sign-In (OAuth2)** to be wired when credentials are added. | Approved |
| **D-019** | **KRA Tax & eTIMS Strategy** | Do **not** block release on slow KRA eTIMS VSCU/OSCU API onboarding. Ship immediate **KRA Tax Readiness** (optional `kra_pin` on Organizations, Owners, and Tenants + **Monthly Rental Income (MRI) 7.5% Tax Summary** & Owner Payout Remittance statements) and keep live eTIMS transmission behind an optional adapter interface. | Approved |
| **D-020** | **Media & File Storage** | **Never store binary files or base64 blobs in PostgreSQL.** Store only **external object URLs + metadata** (`ATTACHMENT` table pointing to Cloudflare R2 / S3 / Cloudinary URLs) for maintenance photos, move-in/move-out inspections, expense receipts, and lease documents. | Approved |
